## Problem

Engineering teams often need small workflow tools before they need a full software product. Requirements need structuring, WCCA inputs need review artifacts, risks need traceable assumptions, and validation gaps need clean summaries. Without a controlled development process, AI-assisted work can become scattered drafts that are difficult to verify, reuse, or publish safely.

## Engineering Context

This case study uses synthetic automotive lighting and electrical engineering examples. The workflow represents generic tool-development tasks for requirements organization, WCCA preparation, risk review, validation planning, and design-review readiness.

No proprietary company, customer, supplier, program, schematic, requirement, part number, BOM, harness, validation, cost, ticket, or internal document detail is used.

## Why Codex Was Useful

Codex was useful as a controlled implementation assistant because it could translate a scoped engineering workflow request into a folder structure, Markdown artifacts, deterministic scripts, tests, reports, and review checklists. The value is workflow acceleration, not engineering approval.

Codex helped reduce setup time for repeatable artifacts while keeping the human engineer responsible for technical correctness and final conclusions.

## How Tasks Were Scoped

Tasks were scoped with explicit boundaries:

- Work only inside the named project folder.
- Do not edit homepage files or unrelated project folders.
- Use only synthetic or sanitized automotive lighting examples.
- Create the requested files and no extra functional expansion.
- Keep final engineering approval outside the AI workflow.

This made Codex output easier to review because the expected file locations, safety boundary, and deliverables were clear before work began.

## How Files Were Constrained

File edits were constrained by naming the allowed project folder and listing protected project areas. The working rule was simple: if a file was not in the approved folder, it was not edited for the task.

For a portfolio-safe workflow, relative project links are used instead of absolute local paths. The artifact describes workflow patterns rather than exposing private repositories, internal folder names, customer documents, or program-specific identifiers.

## How Tests Were Used

Tests are used when Codex builds deterministic tools. For example, calculation engines, CSV loaders, report generators, and validation helpers can be checked with focused unit tests before the outputs are used in a portfolio artifact.

For Markdown-only case studies, validation focuses on file presence, required sections, relative links, synthetic labels, human-review language, and absence of prohibited proprietary details.

## How Proprietary Data Was Avoided

The workflow avoids proprietary data by using synthetic automotive lighting examples, generic IDs, simplified public-safe scenarios, and sanitized workflow descriptions. It does not quote, summarize, or reproduce internal work products. If a real workflow pattern inspires a public artifact, the public artifact is rebuilt using synthetic substitute data.

## Workflow

1. Capture the portfolio-safe task objective.
2. Define the allowed folder and protected files.
3. Write or review the Codex prompt before execution.
4. Generate only the requested files.
5. Validate required labels, review notes, sections, and sanitization boundaries.
6. Review outputs with a qualified engineer before public use.

## Risks and Mitigations

- Risk: Codex may make unsupported engineering claims. Mitigation: require human-review sections and avoid final-approval language.
- Risk: Scope drift may modify unrelated artifacts. Mitigation: constrain work to one folder and review changed files.
- Risk: Synthetic examples may accidentally resemble real work. Mitigation: use generic IDs, generic values, and sanitization review.
- Risk: Tests may be treated as proof of engineering correctness. Mitigation: describe tests as workflow validation, not engineering approval.

## What This Proves for Automotive Engineering Teams

This case study shows that Codex can help engineering teams create controlled workflow tools and review artifacts faster when the task is bounded, deterministic outputs are checked, and engineers retain final authority. It demonstrates a practical way to use AI for requirements structuring, WCCA preparation, risk review, validation planning, and design-review readiness without treating AI as the approver.
